# 跨会话继续同一任务：如何做好 Agent Handoff

Agent 会话是临时记忆。新会话不会天然知道旧会话读过哪些文件、做过哪些决定，也不知道当前任务进行到了哪里。

Handoff 就是把继续工作所需的上下文明确交给下一会话，使接手者可以直接推进，而不是重新询问和调查。

## 什么场景适合使用

### 会话已经很长

当前任务还没有完成，但历史里已经积累了大量搜索结果、失败尝试和工具输出。继续使用原会话可能让重要信息越来越难被关注。

### 工作需要换到另一个会话或工具

例如从一个编码工具切换到另一个工具、换到不同目录或电脑，或者把工作交给另一位同事。

### 大任务需要分阶段完成

规划、实现和审查可能分别占据完整会话。每个阶段结束时留下可恢复状态，下一阶段就不必继承全部过程噪声。

### 中途发现一条独立支线

主任务继续进行，同时把支线工作交给另一个会话。支线需要一份足够独立的背景说明。

## 什么时候不需要 Handoff

- 仍在同一会话中连续完成当前阶段：直接继续；
- 只是一块独立调查，完成后需要返回当前会话：使用子 Agent；
- 仍是同一任务，只需要减少历史长度：使用上下文压缩；
- 前面的内容已经完全无用：直接新建空白会话；
- 想保留当前任务并尝试另一种方案：使用 Fork。

Handoff 的核心价值是让工作能够移动，而不只是把聊天总结得更短。

## 一份 Handoff 应该写什么

交接内容不需要很长，但必须让没有读过旧会话的人知道下一步怎么做。

```markdown
# 任务 Handoff

## 目标
这项任务最终要得到什么，完成条件是什么。

## 权威入口
- 任务记录、代码、设计文档和相关链接

## 已完成
- 只写已经确认或验证的工作

## 已确认决定
- 采用了什么方案，以及为什么

## 当前状态
- 正在处理什么，相关文件有哪些

## 验证结果
- 实际运行过哪些检查，结果如何

## 下一步
1. 第一项可以直接执行的动作
2. 后续步骤和依赖

## 风险与未确认项
- 哪些内容仍然只是推测或需要验证
```

其中最重要的是“下一步”。“继续剩余工作”没有实际入口；“读取任务记录，完成错误状态测试，然后运行生产构建”才足以让新会话直接开始。

## 怎么完成一次交接

### 1. 更新真实状态

先确认任务记录、代码和测试反映当前进度。已经稳定存在于这些地方的内容，只在 Handoff 中提供路径，不要再复制一份。

### 2. 写一份短交接

保留目标、决定、验证、风险和下一步，删除失败尝试、过期方案和无关工具输出。把“已确认事实”和“尚未验证的判断”明确分开。

### 3. 检查可移植性

确认下一会话能够访问所有路径和链接，交接中不包含密码、Token 或私有敏感信息。临时目录中的文件可能在重启后消失，跨天或跨机器时应放到持久位置。

### 4. 新会话从交接文件启动

让新 Agent 先读取项目说明、任务记录和 Handoff，再检查当前文件状态。代码和测试与交接描述冲突时，应以当前环境中的原始证据为准。

### 5. 从第一个明确动作继续

接手后不要重新复盘整个旧会话，也不要立即重做已经验证的工作。先完成 Handoff 中列出的第一项动作，再根据新证据更新任务状态。

## 常见失败

**只写结果，不写原因。** 新会话会重新讨论已经确定的方案。重要决定需要附上简短理由或指向对应文档。

**把推测写成完成事实。** 下一位 Agent 可能不再检查它，错误假设就会成为后续工作的前提。

**复制大量现有文档。** 交接文件很快会和真实任务状态不一致。应引用权威文件，而不是制造第二份事实来源。

**没有可执行的下一步。** 接手者知道发生了什么，却仍然不知道从哪里开始。

**完全相信交接摘要。** Handoff 是经过筛选的二手信息，关键完成声明仍应通过代码、测试或当前环境做最小复核。

## 一句话判断

如果同一任务需要离开当前会话继续，就使用 Handoff，把目标、已确认决定、验证证据和下一步明确带过去。

期待结果回到当前会话，用子 Agent；整个任务向下一会话继续，用 Handoff。
