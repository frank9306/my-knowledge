# 我想做一个“第二个你”：让 AI 真正记住你的工作

我最近一直在想一个问题：今天的 AI 已经能写邮件、做总结、分析数据、生成代码，为什么真正用它工作时，我们还是会觉得累？

一个很直接的原因是，每一次对话几乎都要从头开始。

你要重新告诉它客户是谁、项目做到哪一步、上次为什么做了那个决定、答应过谁什么事情，以及这份文件和另外三份文件之间到底是什么关系。AI 的能力很强，但它不了解你正在经历的那条连续时间线。

所以我想做一个产品，叫 **You²，第二个你**。

它不是另一个更大的聊天框，也不是一个不断截屏的监控软件。我希望它能在用户明确授权的范围内，看见工作、记住经历、理解人物和项目之间的关系，逐渐学会一个人做事的方法，最后按照这个人的方式准备和执行工作。

一句话来说：

> **成为第二个你，按照你的方式帮你做事。**

![一个人在电脑前工作，聊天、邮件、文档和代码等分散线索汇入可追溯的个人记忆，AI 助手在旁协助但不替用户作决定](/images/blog/you2/you2-hero.png)

*概念插画：You² 把分散的工作线索整理为连续、可信、可控的个人上下文。*

## AI 真正缺的，是你的上下文

现代人的工作被切碎在很多地方。需求在聊天软件里，正式承诺在邮件里，数据在 Excel 里，过程在浏览器和业务系统里，判断依据可能只存在于某次会议和几分钟的终端操作中。

信息其实没有消失，只是散落了。

人需要不断搜索、回忆和拼接，AI 则只能看到我们主动复制给它的那一小块。于是出现了一个有些荒诞的局面：AI 可以读懂复杂材料，却不知道你昨天正在做什么；可以草拟一封漂亮的邮件，却不知道你上周已经向对方承诺过什么。

我认为，下一个真正有价值的个人 AI，不应该只拥有更多通用知识，而应该拥有一套属于用户自己的、连续的工作上下文。

它需要知道：

- 你认识哪些人，彼此是什么关系；
- 你同时在推进哪些项目，现在分别处于什么状态；
- 哪些决定已经作出，当时为什么这样决定；
- 你答应过谁什么事情，还有哪些没有完成；
- 你习惯怎样组织文件、表达观点和处理重复工作。

这些内容共同构成了一个人的工作记忆。它们不是一次对话的附件，而是 AI 真正参与工作的基础。

## 从“记录屏幕”到“形成记忆”

电脑屏幕是数字工作的共同出口。邮件、网页、文档、聊天、IDE 和业务系统，最终大多会在屏幕上被查看和处理。这让系统有机会在不要求用户额外写笔记的情况下，理解工作正在发生什么。

但“看见”不等于“记住”。如果产品只是高频截图，再把所有内容塞进向量数据库，它得到的只会是一座越来越嘈杂的仓库。

我设想中的 You² 会建立三层记忆。

![原始事件、工作记忆和长期记忆组成三层结构，证据逐层沉淀，相关上下文在需要时返回](/images/blog/you2/you2-memory-layers.png)

*概念插画：记忆不是把所有内容堆在一起，而是从短期证据逐层提炼出可用的长期上下文。*

第一层是短期保留的原始事件。它记录时间、应用、界面文本和必要的来源证据，主要用于追溯和纠错。

第二层是工作记忆。系统把连续活动切分为任务片段，形成小时摘要和每日总结，帮助用户恢复最近离开时的工作现场。

第三层才是长期记忆。只有稳定且有价值的信息，才会沉淀为人物、项目、事实、决定、承诺、待办和可复用流程。

长期记忆也不能只增不减。它需要合并重复内容、标记过期事实、保留冲突发生的时间、降低临时信息的权重，并允许用户修改和彻底删除。

换句话说，这个产品最难的地方可能不是 OCR，也不是调用哪个模型，而是判断：什么值得记住，什么应该遗忘，什么只是暂时的猜测，以及回答一个问题时能不能找回正确的证据。

## 它应该怎样参与工作

我希望 You² 最终能够完成一条从记忆到行动的完整链路。

比如，客户发来消息询问上次的报价。系统识别出联系人和项目，找回近期讨论、最终版文件以及价格变化的原因，然后提示：

> 张三正在向你索要上次的报价。已找到最终版文件并生成回复，是否预览？

这里有一个很重要的边界：系统可以主动理解和准备，但不能擅自替用户作出承诺。

读取资料、整理背景、生成草稿和制定操作计划，可以在授权范围内自动完成；发送消息、上传文件、删除数据、付款和修改权限等具有外部影响的动作，必须经过用户确认。

我希望它像你一样理解和做事，但重要决定永远由你作出。

## 隐私不是一个设置项

一个持续理解个人工作的产品，天然会接触极其敏感的信息。如果用户不敢一直开启它，其他能力都没有意义。

因此，隐私和控制权不能在产品快完成时再补上，而必须成为最早的架构约束。

我设想的默认原则包括：本地采集、本地 OCR、本地存储；原始屏幕画面默认不上传；密码框、隐私窗口和指定应用默认屏蔽；采集状态始终可见，并且可以用全局快捷键一键暂停。

如果用户选择调用云端模型，产品还应该清楚展示哪些信息会被发送出去。用户能够查看、修改、导出和删除自己的记忆，所有执行动作都留下可追溯的审计记录。

权限也必须分开：允许系统观察，不代表允许它操作；允许它操作应用，也不代表允许它向外提交。网页和文档里的内容只能被视为数据，不能自动变成 Agent 的指令，否则一次提示注入就可能把个人记忆变成攻击者的工具。

## 第一版，我只想证明三件事

产品的终点很远，但 MVP 不应该从“自动替你工作”开始。

第一版我只想验证三个问题：它能不能记得准，能不能找得到，以及用户敢不敢一直开。

因此，MVP 会聚焦于 Windows 上的观察、记忆、检索和纠错：识别活动窗口和屏幕变化，通过系统接口与本地 OCR 获取经过授权的内容，把一天切分成工作片段，生成小时摘要和每日总结，再用关键词与语义检索回答“我之前做过什么”。

每个关键回答都应该带有来源。用户发现记忆不准确时，可以立即纠正或删除。CPU、内存、磁盘和电量占用也必须足够低，不能为了记住工作而妨碍工作本身。

这一阶段暂时不做自动发送、自动付款、多设备同步和团队共享。因为在记忆还不可信时，越强的执行能力只会放大错误。

## 从记得住，到懂得做

如果第一阶段成立，我设想 You² 会沿着五个阶段演进：

![同一个人依次经历记得住、找得到、会准备、能执行和懂得做五个阶段，最终执行仍需要人的确认](/images/blog/you2/you2-roadmap.png)

*概念插画：能力逐步增加，信任也要逐步建立；只有记忆可靠，才值得继续开放执行权限。*

1. **记得住**：完成本地采集、事件切分、摘要、检索和纠错。
2. **找得到**：建立人物、项目、决定、承诺和文件之间的关系。
3. **会准备**：根据当前场景找回信息，生成材料和下一步建议。
4. **能执行**：在用户确认后，完成受控的跨应用操作。
5. **懂得做**：把用户反复验证过的方法沉淀为可编辑、可审计、可复用的个人技能。

这条路径不是简单地逐步增加功能，而是在逐步建立信任。只有先证明记忆可靠，准备工作才有意义；只有准备结果长期可控，执行权限才值得交给它。

## 我真正想做的，不是一个全知的 AI

我不认为“第二个你”意味着复制一个完整的人，也不希望它成为替用户作主的数字分身。

我真正想做的是一种能力的延伸：当你忘记时，它能帮你找回；当信息散落时，它能重新建立联系；当重复工作再次出现时，它已经知道你上次是怎么完成的；当它准备采取行动时，你仍然拥有最后的决定权。

You² 目前还是一个产品构想，许多关键假设都需要验证：用户是否接受持续感知，什么信息值得长期保留，本地模型能否在性能与准确度之间取得平衡，以及人们是否愿意为这种长期记忆付费。

但有一件事我越来越确定：个人 AI 的核心竞争力，不会只是模型更聪明，而是谁能建立一套长期可信的个人上下文，并在正确的时刻，只取回真正相关的那一小部分。

先做到记得准、找得到、用户敢一直开。

然后，再慢慢成为第二个你。
