本章学习目标

本案例将介绍如何训练自己的模型。具体而言，你将能够：

  • 解释 ChatGPT 风格大语言模型的端到端训练流程，区分各阶段的目的与机制：分词、预训练、中期训练和监督微调。

  • 配置并训练字节对编码（BPE）分词器，阐明选择词表大小时的权衡。

  • 从机制层面描述 Transformer 架构，包括注意力头、网络层数与嵌入维度。你将研究这些超参数如何与模型容量和计算预算相互影响。

  • 使用标准基准（ARC-Easy、ARC-Challenge、GSM-8K）评估训练后的语言模型，并批判性地解读结果，包括其失效模式。

  • 批判性地思考大语言模型训练涉及的伦理、环境与可及性问题，包括作为准入门槛的成本，以及蕴含价值判断的数据整理选择。

  • 查找并浏览开放访问大语言模型的相关信息，包括阅读模型卡、训练报告、大语言模型训练代码及其他类型的模型平台条目。

5.1 构建聊天机器人

我们将完成一个涵盖现代 ChatGPT 风格语言模型完整生命周期的实践案例。使用 nanochat，11 1 https://github.com/karpathy/nanochat，这是 Andrej Karpathy 于 2025 年 4 月发布的指令遵循大语言模型的精简、单代码库、全栈实现。早期 nanoGPT 仅涵盖预训练，nanochat 则实现完整流水线：字节对编码词元化器、网页文本预训练、随后在基准数据集上监督微调（SFT）、推断服务器和聊天网页界面。

代码主要使用纯 Python，依赖极少，因而易于使用和扩展。代码库约有 8000 行 Python 和少量 Rust。22 2 如果这个数字听起来很大，须知道对应专有系统往往有数百万行代码。nanochat 旨在成为一个小型自包含版本。

nanochat 的表现令人瞩目：仅需 48 美元（∼\sim2 小时的 8xH100 GPU 节点），即可训练具有 GPT-2 能力的大语言模型（2019 年训练成本为 ∼\sim43,000 美元 [Radford et al., 2019]）。这种算力对于普通大学学生项目虽不算常见，但可缩小实验，使其适用于实践课程作业。要意识到，从原始字节到可用聊天助手，每次梯度更新和每个设计决策都可见。我们将通过四项全部需要完成的任务，带你走完 nanochat 流水线。

由于课程 GPU 预算有限，你将训练小模型（深度为 4，视可用资源而定，见第 5.3 节），然后结合理论和已发布的 nanochat 基准，反思更大规模时可能发生什么。

5.2 背景：Karpathy 的 nanochat

本案例让你亲自实践现代大语言模型训练流水线的每个阶段，从输入文本到部署聊天助手。它将第 2–4 章的理论概念落实为具体、可调试的代码。

nanochat 开箱即用，只需设置一个复杂度旋钮 --depth，指定 Transformer 层数，就能训练计算最优模型。其余超参数——嵌入宽度、注意力头数、学习率调度、训练时长、权重衰减——都以近最优方式自动推导。这使配置空间易于管理，同时保留理解每个参数作用的全部教学价值。

训练流水线按现在你应该已经熟悉的阶段进行，下面简要说明。

预训练

模型在取自 CLIMBMix [Diao et al., 2026] 的约 60 亿词元上训练，该数据集是基于聚类、迭代自举的数据混合语料库。深度 24（∼\sim14 亿参数）的模型在 4×\timesH100 节点计算集群上约 4 小时，可达到 2.41 的验证损失（每字节 0.717 比特）。

监督微调（SFT）

从预训练检查点出发，模型在指令遵循和推理混合数据上微调：SmolTalk [Ben Allal and others, 2024]（46 万次通用对话）、MMLU（知识选择题，3 轮）、GSM-8K（小学数学，4 轮）、身份对话和合成拼写任务，总计约 110 万训练样例。注意，交叉熵损失只在助手词元上计算，不在用户提示上计算，与 InstructGPT 训练过程一致 [Ouyang et al., 2022]。

每个训练阶段之前，使用 Rust 实现在 20 亿字符上训练 BPE 词元化器，不到一分钟便产生包含 32,768 个词元的词表。

项目内置网页推断服务器和轻量 JavaScript 聊天界面，可以立即与你训练的模型互动。

补充资源

两门免费课程为本案例材料提供互补视角。Hugging Face LLM Course [Hugging Face, 2022] 介绍 transformers、datasets、tokenizers 和 accelerate 库，以及当今多数开放权重模型发布与评估所在的 Hugging Face Hub。Mathieu Labonne 的 LLM Course [Labonne, 2023] 提供实践路线图，涵盖预训练数据整理、参数高效微调（LoRA、QLoRA）、偏好对齐（DPO、PPO、GRPO）、量化（GGUF、GPTQ）及生产推断服务（vLLM、TGI）。这些资源共同将 nanochat 放入更广的开源大语言模型生态中，任务 3 和 4 会明确引用。你也可自由寻找额外资源。强烈建议在报告必要之处添加来源链接和引用。

5.3 实验准备

代码仓库

克隆课程仓库，在编写代码前仔细阅读 README。

计算资源

无须专用计算资源，可以使用自己的笔记本（配有 GPU）或更大计算机。实验设计为每次运行最长约 8 小时。预训练使用 --depth 4 配置；只有硬件不允许更大模型时，才可使用 --depth 2。除非拥有强劲硬件，否则不要尝试深度 ≥\geq12。

日志

nanochat 按可配置间隔在终端记录训练损失、验证损失及每字节比特数，并提供运行期间报告和保存信息的额外功能。因此，最好从开始就启用写入 .jsonl 文件的结构化日志。运行后再补日志很痛苦。可以尝试不同日志文件格式。建议在训练完整模型前使用 wandb.ai 等服务。

5.5 任务 1：词元化

5.5.1 要做什么

使用 nanochat 的 Rust 词元化器训练程序，在 CLIMBMix 数据集的 5 亿字符样本上训练 BPE 词元化器。执行两次实验，词表大小分别为 8192 和 32,768 个词元。

5.5.2 交付内容

  • •

    一个可复现词元化器训练过程的短脚本。

  • •

    一节报告（最多 1 页），用自己的词元化器输出作为证据回答以下问题：

    1. 1.

      什么是 BPE，它与词级、字符级词元化有何不同？为具体例子绘制合并树（可以从数据中找，也可以自己构造，但不要复用现成示例！）。务必包含各次合并的计数。

    2. 2.

      对于固定文本样本，词表大小如何影响压缩率（每字符词元数）和序列长度？展示两个词元化器在英语文本上的测量结果。

    3. 3.

      为什么词表大小对下游语言模型很重要？回答时考虑嵌入矩阵大小、softmax 分母，以及为罕见词元学习可靠表示的挑战。

    4. 4.

      观察到哪些异常现象或失败情况？词元化器如何处理数字、源代码或非英语文本？

注意：BPE 解释是否正确；实证证据的质量；词表权衡分析的深度；失败案例讨论是否敏锐。

5.6 任务 2：预训练

5.6.1 要做什么

使用 nanochat，以 --depth 4（计算机不够快时用 --depth 2）在 CLIMBMix 上预训练 Transformer。定期在检查点记录训练损失、验证损失和每字节比特数。

5.6.2 交付内容

  • •

    训练集与验证集的每字节比特数曲线（绘图并纳入报告）。使用 bpb，而非原始损失。

  • •

    保存的模型检查点。

  • •

    一节报告（约 2 页），涵盖：

    1. 1.

      深度参数：解释 nanochat 中 --depth 参数控制什么，代码库如何从它自动推导其他全部超参数：嵌入宽度、注意力头数、学习率调度和训练时长。对于所选深度，说明层数、注意力头数、嵌入维度、可训练参数总数及模型将训练的总词元数。单一旋钮设计对这样的代码库为何有用？相较单独调节每个超参数，有何局限？

    2. 2.

      缩放定律：使用 Chinchilla 框架 [Hoffmann et al., 2022]，根据模型参数数目计算计算最优训练词元数。nanochat 默认训练时长与之相比如何？训练不足和过度训练分别意味着什么？

    3. 3.

      损失分析：将训练期间每字节比特数（bpb）的变化画成训练曲线，并解释形状。曲线何时变平？训练与验证之间的差距说明什么？

    4. 4.

      定性检查：在不使用系统提示的情况下，从预训练模型采样五个补全文本（原始下一词元预测）。这一阶段模型能做什么？你认为为什么如此？

注意：深度参数和自动配置说明是否正确；架构描述是否准确；缩放定律计算是否应用正确；损失分析的质量；定性评估是否有洞见。

5.7 任务 3：中间训练与监督微调

5.7.1 要做什么

回顾一下，nanochat 只执行两个训练阶段：预训练和 SFT。但书中讨论过，额外的中间训练阶段可以改善模型表现。本任务中，你将修改 scripts/chat_sft.py，实现新的中间训练阶段，目标是将推理适配（中间训练）与指令遵循（SFT）分开，并实证测量效果。

阶段 1——中间训练

修改 chat_sft.py 中的 train_tasks 列表，只包含推理和知识任务 MMLU、GSM-8K。移除其他所有对话与拼写数据。从预训练基础检查点运行 chat_sft.py，保存得到的检查点。

阶段 2——SFT

再次修改 chat_sft.py，使 train_tasks 只包含 SmolTalk。还需小幅修改脚本，使其加载阶段 1 检查点，而非预训练基础模型。可从检查 chat_sft.py 中的 load_model 调用开始。44 4 提示：阅读 nanochat/checkpoint_manager.py，理解如何定位检查点。从阶段 1 检查点运行 chat_sft.py，在中间训练之后继续 SFT。

每个阶段之后，用 scripts/chat_eval.py 在 ARC-Easy、ARC-Challenge 和 GSM-8K 上评估。

合理性检查：运行阶段 1 前检查数据，打印 MMLU 和 SmolTalk 的前几行，理解格式与内容。确保能回答：每个数据集贡献多少训练样例，一个训练样例是什么样的？

5.7.2 交付内容

  • •

    两个检查点，每阶段（中间训练和 SFT）各一个。

  • •

    各阶段之后 ARC-Easy、ARC-Challenge 和 GSM-8K 的评估分数，以表格报告，纳入报告（见下文）。

  • •

    一节报告（约 3 页），涵盖：

    1. 1.

      实现：描述为实现分阶段训练而对代码库作出的修改。列出训练实验采用的超参数。可以自由尝试不同设置！

    2. 2.

      损失掩码：为什么 SFT 损失只在助手词元上计算？构造具体词元级例子，说明使用与不使用掩码时损失分别是什么样。

    3. 3.

      数据集分析：对每阶段，描述所用数据集、近似规模，以及为何特意为该阶段选择它。数据集训练划分可能包含什么价值观或潜在偏见？它们可能如何塑造模型行为？

    4. 4.

      基准分数：用表格报告各阶段评估分数。阶段 1 与阶段 2 之间有什么变化，为什么？还须与预训练结果比较，使分析涵盖全部三个阶段。注明令人意外的结果。

    5. 5.

      参数高效微调：nanochat 执行全量微调，SFT 期间更新每个参数。描述 LoRA（低秩适配）及其量化变体 QLoRA 与全量微调的不同。它们在计算、内存和最终模型质量方面有什么权衡？对于目前训练采用的深度，你是否推荐 PEFT 技术？

注意：实现描述是否正确清晰；损失掩码解释是否正确；数据集分析的批判性质量；基准分数及其解释是否准确完整；LoRA／QLoRA 比较的概念准确性。

5.8 任务 4：推断、部署与批判性反思

5.8.1 A 部分：推断与部署

启动 nanochat 的推断服务器和网页界面，与你训练的模型互动。然后在报告中回答以下内容（约 1 页）：

  1. 1.

    推断循环：描述自回归采样如何工作，包括键—值（KV）缓存如何避免解码步骤之间的重复计算。尝试不同参数解码：什么是温度？改变它（尝试 0.1、0.7、1.5）如何影响输出质量和多样性？展示并讨论自己模型的五个代表性例子。

  2. 2.

    生产加固：指出 nanochat 推断服务器在生产规模部署之前，需要进行的三项具体工程改动。

  3. 3.

    能力比较与缩放：查找至少两个公开可用模型在 ARC-Easy、ARC-Challenge 和 GSM-8K 上发布的基准分数：一个与你的 nanochat 模型规模相近，一个明显更大。可选择任何推断设计的分数（如零样本、少样本等），但须报告具体条件。Hugging Face Hub 上的模型卡和排行榜是良好起点，引用每个所用来源。构建表格，将自己的结果与已发布数据并列。然后回答两问：相对于相似参数数量的模型，你的模型处于什么位置？它与同规模、充分训练模型的差距，揭示了数据质量、训练时长和对齐怎样的作用？

5.8.2 B 部分：批判性反思

撰写简短讨论（约 0.5–1 页），回应下列三个题目之一。

题目 1——可及性与普及：nanochat 的醒目宣称是“100 美元能买到的最佳 ChatGPT”，使个人也能训练大语言模型。批判性评价这一说法。还有谁无法使用这条流水线，为什么？

题目 2——数据与价值观：nanochat 在 CLIMBMix 上预训练，这是基于聚类、迭代自举的数据混合语料库。构建该数据集时作出了哪些决策，其中包含谁的价值观？不同的预训练语料库如何可能带来性质不同的模型？

题目 3——环境成本：nanochat 的“可负担”训练大约消耗 8×\timesH100 GPU 的四小时运行。用成熟方法（如 ML CO2 Impact 计算器）估算自己训练的碳成本。55 5 https://mlco2.impact.compute.org 将它置于大语言模型环境影响的更广背景中。便宜是否等于低影响？

A 部分注意：推断循环描述是否正确；生产加固建议是否可行；基准说明是否完整；对最先进水平的讨论是否相关。

B 部分注意：分析深度、证据使用，以及质疑假设的意愿。

5.10 结语

本章以 nanochat 为窗口，考察完整大语言模型训练流水线。你训练了 BPE 词元化器，观察 Transformer 从网页文本学习，使模型适应指令遵循，在标准基准上评估，并将其部署为聊天助手。

你的深度 4 模型与前沿之间的差距会很明显，因为我们并不期望你有数据中心级计算能力。不过，理论上这些实验可以扩展：以更高深度和更多数据重新运行，应如缩放定律预测那样产生能力更强的模型。完成作业 1 后，你实质上已独自训练了完整大语言模型，也更有能力在未来进行需要更大规模的实验。
