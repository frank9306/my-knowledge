本章学习目标

本案例将通过实践，让你学习构建用于推理任务的自我反思智能体。具体而言，你将能够：

  • 在谜题与游戏基准上运行多步推理智能体。

  • 用自己的想法改进推理智能体。

  • 实现自己的自我反思智能体。

  • 批判性地思考学习型智能体在谜题与游戏领域中的表现和稳定性。

10.1 BALROG 概述

本案例将使用一个进行自我反思的智能体式大语言模型。我们采用名为 BALROG 的常用推理任务基准套件。11 1 Balrog（炎魔）是 J.R.R. Tolkien 奇幻作品中中土世界的神话恶魔。即便最强大的巫师灰袍甘道夫，也会遭遇炎魔这一劲敌。BALROG 是 Benchmarking Agentic LLM and VLM Reasoning On Games 的首字母缩写，意为在游戏中评测智能体式大语言模型和视觉语言模型的推理能力。BALROG 基准结合了简单与困难游戏，正如 BALROG 论文自身的基准研究所示，其中某些游戏很难让大语言模型玩好 [Paglieri et al., 2025]。

最初，BALROG 游戏使用普通大语言模型进行评测。不过代码相当开放，便于编写自己的智能体方法，看看能否获得更好的成绩。该软件旨在让你编写用于上下文（强化）学习的智能体代码。

BALROG 的主网站是 https://balrogai.com。代码易于调整并用于自己的实验，还提供排行榜。本章将引导你编写自己的智能体代码，再将其用于 BALROG 游戏套件。

BALROG 旨在以推理问题挑战上下文智能体。它使用谜题类游戏评测大语言模型和视觉语言模型的推理能力。图 10.1 列出了这些游戏。难度由低到高依次为 BabyAI、Crafter、TextWorld、BabaIsAI、MiniHack 和 NetHack。游戏提供多种挑战，有些基于文本，有些包含视觉部分，但都包含模型推理挑战。其中一些被认为很难。例如，我们并不期望你的模型、智能体，或你本人在 NetHack 中取得高分。（如果在没有查阅作弊攻略的情况下做到了，或许可以考虑为顶级人工智能会议写一篇论文。）

10.1.1 谜题与游戏

BALROG 由图 10.1 所示的六种谜题和游戏组成，从简单网格世界谜题，到困难的基于文本的地下城与龙式策略游戏；后者的回合信用分配跨度很长，奖励景观平坦。

BALROG 作者提供了一个支持智能体实验的代码库，你可以设计自己的智能体，观察它们在基准上的表现。要在 BALROG 基准上表现良好，智能体必须擅长推理和规划，而且很可能还需要善于适应并反思自身行为。

BabyAI 是简单的网格世界游戏，智能体必须解决导航任务。一个简单的强化学习类算法就能轻松解决。任务以自然语言给出，例如：走到蓝色球那里，然后捡起灰色钥匙。当然，智能体式大语言模型的挑战在于完成任务的规划部分。我们期望它在这个简单游戏上表现良好（见 BALROG 论文）。

另一方面，NetHack 是高度具有挑战性的游戏，对人类玩家也如此。NetHack 是一种基于文本、类似地下城与龙的游戏。它既包含长期战略规划，因为赢得一局可能需要数十万步，也包含抵御常见成群怪物的短期战术战斗。在 NetHack 中，信用分配是一项挑战：要理解智能体过去哪些行动促成了最终成功或失败，因为在游戏某个区域采取的行动，可能在远处产生意想不到的后果，这使强化学习智能体难以游玩。众所周知，人类玩家若不借助作弊攻略，可能需要数年才能精通 NetHack。

10.1.2 BALROG 架构

现在查看 BALROG 框架的架构。图 10.2 展示了该架构，摘自论文 [Paglieri et al., 2025]。

请熟悉 BALROG 系统。阅读可在 https://arxiv.org/abs/2411.13543 找到的论文 Paglieri et al. [2025]，或者访问 BALROG 网站 https://balrogai.com。

如果尚未安装，请使用 git clone 命令将 BALROG 安装到系统上。访问 https://balrogai.com，或直接访问 Github 仓库 https://github.com/balrog-ai/BALROG。将该仓库安装到本地计算机。

决定使用哪个大语言模型。请注意，典型的 BALROG 智能体在每一步都会多次调用大语言模型。如果想本地运行模型，请安装它，或从 Huggingface 使用它。如果想使用商业云端大语言模型，请获取 API 密钥，并在环境中配置。若有免费的学生档位，可以考虑申请。使用前沿模型可能很贵，但较旧、较小的一些模型仍具有相当能力，通常便宜得多。

Github 仓库中的 BALROG 自述文件包含系统安装方法，以及如何为喜欢的大语言模型配置 API 密钥，见代码清单 10.3。（在其中一项练习中，我们将使用多个大语言模型比较性能。目前只是先让系统运行起来，用哪个都可以。）

10.1.3 智能体

请阅读 BALROG 智能体教程 https://github.com/balrog-ai/BALROG/blob/main/docs/agents.md。在 BALROG 中，智能体是一小段 Python 代码，通过提示调用大语言模型，让它回答如何决定下一步。智能体代码负责接收模型的答案（观测），并选择下一个行动。大语言模型用于执行各种提示。

BALROG 遵循图 9.7 中的交互方式 D，依据交互历史构建提示。

10.1.3.1 提示构建器

智能体根据以前的行动，即先前交互中的观测与行动对，构建提示。因此，用强化学习术语来说，智能体实现策略功能，根据传入观测选择下一步行动。

前往 prompt_builder 目录，更改从行动历史构建提示的方式。

10.1.3.2 智能体

智能体负责记忆功能：管理观测与行动历史。智能体必须记录过去的观测和行动，以支持考虑上下文的决策，这需要由我们在大语言模型之外实现。

BALROG 的智能体代码查询大语言模型：智能体将观测发送给模型，接收回应，再根据回应决定游戏中的行动。

BALROG 附带若干预先编写的智能体，你应研究它们以设计自己的智能体。仓库包含朴素智能体和思维链智能体，还提供了处理大语言模型回应的更稳健版本。

构建自己的智能体时，你很可能会以自定义智能体为基础。BALROG 智能体教程提供了一个简单规划智能体的示例。

10.2 实现步骤

下面提供一些练习，帮助你探索智能体构建。

10.2.1 复现论文

先尝试复现 BALROG 论文中的结果。请查看 Github 上的 BALROG 代码 https://github.com/balrog-ai/BALROG。阅读评估指南、智能体开发教程，以及如何运行少样本学习（上下文学习）实验的说明。在计算机上安装相关工具和正确的 Python 版本（并将其加入 PATH）。从命令提示符启动 Python 解释器检查版本：$ python。

首先运行标准评估，确保安装正确，见代码清单 10.4。

10.2.2 不同的大语言模型

为了解标准智能体在不同基准、不同大语言模型下的表现，运行几种不同模型很有帮助。建议运行闭源和开放模型，观察表现。尤其可以尝试来自 OpenAI、Claude、DeepSeek、OLMo 和 Qwen 的开放版本，它们可能表现良好。

运行这些模型很重要，可让你更深入理解各模型的相对优势。

10.2.3 不同谜题

接下来，为更好理解基准，应在不同谜题中运行大语言模型智能体之后，仔细查看模型提示与答案。看看能否发现智能体在哪里失败、弱点是什么。通过仔细检查每个行动、深入理解谜题，你或许能想到改进智能体的方法。

10.2.4 计算成本

BALROG 智能体每走一步都会调用大语言模型，通常使用长提示。这些谜题与游戏需要很多步骤。在不同随机种子下，用不同模型运行完整基准，很容易消耗大量词元。

实验时，先尝试小而便宜的模型，例如 Qwen-3B。从最简单的基准（BabyAI 和 Crafter）开始。如果想扩展，请继续，但要关注计算成本。你既希望获得见解，也希望实验能在合理时间和成本内完成。

10.2.5 实现自己的推理智能体

现在可以实现自己的学习智能体了。前往 balrog 的 agents 目录，编辑 custom.py 文件。代码清单 10.5 转载了 BALROG 自述文件中的自定义智能体代码。可用代码清单 10.6 中的命令运行代码（指定自定义智能体，并使用较少工作进程，以较低负载运行）。当然，也可以在命令中指定自己选择的大语言模型。

从提供的代码开始，运行并观察其工作方式。然后尝试小幅改进。可以调整大语言模型提示，或改变 Python 代码处理智能体学习的方式，包括历史提示构建器、规划部分或学习算法。

10.3 评估

BALROG 会以进度百分比报告智能体性能。记录每个基准及每种尝试过的智能体类型的进度数值。应以结构化方式完成；可以编写 Python 或 shell 脚本，自动运行实验并记录结果，也可将进度绘制成图。可以考虑使用 wandb.ai。

哪些智能体类型表现良好，又在哪些基准上表现良好？建立矩阵，记录尝试过的智能体类型与基准类型对应的进度。

注意，大语言模型实验本质上是不确定的：使用同一提示运行两次可能得到不同结果。因此，每项实验应运行多次。如果连续五次得到相同结果，就可以开始信任。如果变化很大，则应调查原因。是纯粹统计性的原因吗？降低温度能解决问题，还是存在其他问题？

不要盲目信任报告的进度数值。因为你是在计算机上运行代码，可能存在错误或其他问题。BALROG 系统便于深入检查运行过程。它会记录 csv 文件，可用电子表格查看。查看一些运行，判断看到的情况是否合理，还是智能体表现出退化行为。如果是后者，尝试找出原因。你做错了什么吗？基准与智能体行为之间是否存在意外干扰？奖励景观是否过于平坦，导致智能体没有可追随的信号，只会随机行动、毫无意义地兜圈子？对此你能做些什么？

请注意，大语言模型领域，尤其是智能体式大语言模型领域，还很新，我们的认识与软件框架尚未稳定。出现一些意料之外的结果是正常的，也可能遇到挑战或挫败。

结构化实验与结果记录是你的好帮手。规划和组织能让实际智能体式大语言模型实验的运行、评估和改进成为愉快的练习。

10.4 自我反思

当你能够复现基准结果，并已对智能体进行一些实验后，可能想迎接更大的挑战。本节尝试扩展 BALROG 智能体，使其具备自我反思：让大语言模型承担评估、行动选择等不同角色。与任何追逐一个本身也在被优化的目标的自适应系统一样，自我反思可能容易出现不稳定和振荡。因此，在尝试自我反思思路之前，务必确保上一小节的基础学习系统能正常工作，并以稳定、可预测的方式收敛。请回到该节，确保系统按预期运行。

近期有很多研究尝试改进大语言模型智能体。这里提及两种：ReAct [Yao et al., 2022] 和 reflexion [Shinn et al., 2024]。ReAct 主要关注提示，而 reflexion 引入新的智能体算法，包括短期和长期记忆。

ReAct

ReAct 使用提示与世界互动。它提倡使用工具查找信息，见图 10.7。ReAct 原始网站为 https://react-lm.github.io，代码仓库为 https://github.com/ysymyth/ReAct。LangChain22 2 参见 https://docs.langchain.com/oss/python/langchain/overview 和 BeeAI33 3 参见 https://github.com/i-am-bee/beeai-framework/blob/main/python/examples/agents/react.py 框架也实现了 ReAct 提示。

查看这些框架，了解 ReAct 引入的基于提示的智能体交互方式。然后在 BALROG 中实现这种交互。它是否改善性能？哪些游戏能从外部信息查询中受益？哪些不能？

Reflexion

ReAct 基于提示，支持交互式查询；reflexion 方法则引入以 Python 编写的智能体，支持更复杂的行为。Reflexion 在不同上下文中使用同一个大语言模型，并提供不同提示。其假设是：批评现有提示的问题，比提出一个有效提示更容易。

Reflexion 是一种常用的自我反思架构 [Shinn et al., 2024]。其主网页为 https://github.com/noahshinn/reflexion。介绍主要思想的博客文章在 https://nanothoughts.substack.com/p/reflecting-on-reflexion。

图 10.8 展示 reflexion 的总体概念、不同提示和不同记忆类型。图 10.9 展示其代码，在第 3、5、6 行（MaM_{a}、MeM_{e}、Ms​rM_{sr}）以及第 9、11、12 行分别调用大语言模型。注意，这些是伪代码，记忆管理、提示管理及收敛准则等重要细节仍未明确。请查看 Github 仓库中的详情。

Reflexion 使用同一大语言模型配合不同提示，可能导致学习不稳定和循环。此外，其记忆管理相对简单，可能发生上下文超限。一种思路是在 Python 中手工实现分块或其他记忆压缩方法，或使用大语言模型实现。

先试用 reflexion 仓库，尝试让它在 AlfWorld、HotpotQA 等 reflexion 应用中运行。

扩展

现在尝试在 BALROG 中实现 reflexion 智能体，运行 BALROG 基准。遇到了什么问题？与标准 BALROG 智能体相比，reflexion 是否改善性能？

接下来进一步扩展问题。可以在文献中寻找其他反思方法，或尝试自行创造新的方法。可以尝试不同应用类型，观察方法的表现。当然也可以尝试其他大语言模型。

10.5 结语

本章讨论了一个实际案例，观察大语言模型如何进行自我反思。我们采用了常用推理任务基准套件 BALROG。它结合由易到难的游戏，其中一些很难让大语言模型玩好。BALROG 套件采用开放设计，可以编写自己的智能体代码，并运行在其中的游戏上。

这是一个重要的实际案例研究。你探索了编写用于上下文推理的智能体代码，还通过实现自我反思超越了基础学习，并在不同大语言模型及极具挑战性的基准上探索了自我反思的稳定性。
